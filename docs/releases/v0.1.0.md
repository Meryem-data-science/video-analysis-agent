# Video Analysis Agent v0.1.0

Première release publique de **Video Analysis Agent**, un agent explicable
d’analyse multimodale local-first pour les vidéos courtes.

## Fonctionnalités principales

- inspection FFprobe et stratégie d’analyse ;
- segmentation PySceneDetect et extraction FFmpeg des frames ;
- grilles et composites de mouvement avec Pillow ;
- extraction audio, analyse locale et transcription faster-whisper optionnelle ;
- fusion audio-visuelle par chevauchement temporel ;
- packs VLM et prompts reproductibles par segment ;
- validation stricte des résultats avant construction du rapport ;
- runs isolés par identité SHA-256 et checkpoints vérifiables ;
- CLI, serveur MCP, API FastAPI et interface React/TypeScript ;
- file locale asynchrone avec progression par étape ;
- démonstration synthétique et framework d’évaluation local.

## Modes VLM

- `manual`, par défaut : prépare les packs sans SDK, clé ou appel cloud ;
- `disabled` : termine les traitements locaux avec le statut `local_complete` ;
- `automatic` : exige un provider explicite ; seul `gemini` est disponible dans
  cette version.

Gemini est facultatif et ses coûts ou quotas dépendent du fournisseur. Les
utilisateurs doivent vérifier les conditions applicables avant de l’activer.

## API et frontend

FastAPI expose les runs, scènes, artefacts, imports VLM, validations et rapports.
`POST /api/jobs` lance une analyse dans une file en mémoire sans maintenir la
requête ouverte. Le frontend permet l’upload, le suivi, la timeline, le parcours
manuel et l’évaluation sans passer par Swagger.

## Démonstration reproductible

`video-agent generate-demo` produit localement une vidéo verticale synthétique de
18 secondes, sans téléchargement ni média protégé. L’interface peut lancer ce
run puis charger des fixtures VLM explicitement simulées et liées au hash exact
de la vidéo.

## Qualité et tests

La suite de release couvre le pipeline, l’identité des runs, les checkpoints,
les trois modes VLM, la validation stricte, l’API, les jobs, la sécurité des
artefacts, la démonstration, l’évaluation et le frontend. La CI cible Windows
Python 3.12/3.13, Linux Python 3.12 et Node 22.

## Benchmark de référence

Dataset synthétique v1, Windows 11, Python 3.13.13, FFmpeg 8.1.1, huit CPU
logiques, audio désactivé et VLM `disabled` :

| Mesure | Résultat |
|---|---:|
| Durée | 18,0 s |
| Scènes attendues / détectées | 3 / 3 |
| F1 des limites à ±500 ms | 1,000 |
| Couverture temporelle | 100 % |
| Frames extraites | 24 |
| Médiane, 2 runs | 19,204 s |
| Écart-type population | 0,054 s |

Ces temps ne sont pas directement comparables entre machines ou configurations.
Les métriques lexicales VLM ne mesurent pas scientifiquement la compréhension
sémantique.

## Limites connues

- FFmpeg reste une dépendance système ;
- la file et l’historique des jobs ne survivent pas au redémarrage ;
- un FFmpeg ou Whisper déjà lancé n’est pas interrompu de force ;
- les modèles Whisper peuvent être téléchargés au premier usage ;
- l’API locale ne fournit pas encore d’authentification ;
- les anciens outputs basés sur le nom de fichier ne sont pas migrés ;
- aucun verrou interprocessus ne protège encore un même `run_id`.

## Confidentialité et fournisseurs cloud

Les modes `manual` et `disabled` n’appellent aucun VLM. En mode `automatic`, des
frames, textes, transcriptions ou extraits audio peuvent être transmis à Gemini.
Il appartient à l’utilisateur de vérifier consentement, confidentialité, base
légale, coûts et conditions du fournisseur.
